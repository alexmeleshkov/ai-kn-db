## Overview

An intelligent chart visualization system that automatically detects chartable data from SQL query results and provides interactive bar, line, and pie chart options. Charts appear below query result tables with a toggle button, allowing users to switch between chart types.

**Key characteristics**:
- Automatic data analysis to determine if results are chartable
- Three chart types: bar, line, and pie (pie only for single-series data)
- Toggle button to show/hide chart visualization
- Type selector buttons to switch between chart types
- Color-coded datasets with predefined palette
- Responsive chart sizing with maintainAspectRatio

## Visual Elements

### Main Components

**Chart Toggle Button** (QueryChart.tsx:145-154):
- **Location**: Below query result table, before chart container
- **Contains**: Chart icon (SVG grid), "Show Chart" or "Hide Chart" text
- **Purpose**: Toggle chart visibility
- **Visual style**: Secondary button, icon + text inline, left-aligned

**Chart Container** (QueryChart.tsx:144-191):
- **Location**: Below toggle button when showChart is true
- **Contains**: Chart type selector, chart wrapper with canvas
- **Purpose**: Houses chart controls and visualization
- **Visual style**: Bordered box or card, padding, background

**Chart Type Selector** (QueryChart.tsx:158-179):
- **Location**: Top of chart container, horizontal button group
- **Contains**: "Bar", "Line", "Pie" buttons (Pie only if single dataset)
- **Purpose**: Switch between chart types
- **Visual style**:
  - Horizontal button group, inline layout
  - Active button: Highlighted (bold, background, or underline)
  - Inactive buttons: Muted or secondary style

**Chart Wrapper** (QueryChart.tsx:181-187):
- **Location**: Below type selector, within chart container
- **Contains**: Chart.js canvas element (Bar, Line, or Pie component)
- **Purpose**: Renders actual chart visualization
- **Visual style**:
  - Fixed or responsive height (e.g., 300-400px)
  - maintainAspectRatio: false for controlled sizing
  - Legend at top showing dataset labels

**Chart Legend** (QueryChart.tsx:137-139):
- **Location**: Top of chart area, generated by Chart.js
- **Contains**: Color swatches + dataset labels (column names)
- **Purpose**: Identifies what each color/line represents
- **Visual style**: Horizontal layout, small squares + text labels

### Interactive Elements

**Toggle Button** (QueryChart.tsx:145-154):
- **Click**: Shows/hides chart container, button text toggles "Show Chart" ↔ "Hide Chart"
- **Visual feedback**: Hover state, cursor pointer

**Chart Type Buttons** (QueryChart.tsx:159-177):
- **Click**: Changes chartType state, re-renders chart with new type
- **Visual feedback**: Active state (highlighted), hover on inactive buttons

**User Actions**:
- **Click "Show Chart"**: Chart container appears with default bar chart
- **Click "Hide Chart"**: Chart container collapses, only toggle button visible
- **Click "Bar"**: Switch to bar chart visualization
- **Click "Line"**: Switch to line chart visualization
- **Click "Pie"**: Switch to pie chart (only available for single-series data)
- **Hover chart elements**: Chart.js tooltip shows exact values

**Visual States**:
- **Hidden**: Only toggle button visible ("Show Chart")
- **Visible (Bar)**: Chart container open, bar chart displayed, "Bar" button active
- **Visible (Line)**: Chart container open, line chart displayed, "Line" button active
- **Visible (Pie)**: Chart container open, pie chart displayed, "Pie" button active
- **Not Chartable**: No toggle button or chart shown (component returns null)

## User Flows

### View Chart from Query Results

1. User asks question: "Show sales by category"
2. Query executes, table displays with category names and sales values
3. System analyzes data: finds string column (category) and numeric column (sales)
4. "Show Chart" button appears below table
5. User clicks "Show Chart"
6. Chart container expands with bar chart (default)
7. User sees visual representation of data

### Switch Chart Types

1. Chart is visible in bar chart mode
2. User clicks "Line" button
3. Chart re-renders as line chart with same data
4. User clicks "Pie" button (if available)
5. Chart re-renders as pie chart

### Hide Chart

1. Chart is visible
2. User clicks "Hide Chart" button
3. Chart container collapses
4. Button text changes to "Show Chart"
5. User can show again by clicking

### Handle Non-Chartable Data

1. User asks: "Show user emails"
2. Query returns table with text-only columns (no numeric data)
3. System analyzes data: no numeric columns found
4. No "Show Chart" button appears
5. User sees only table (charts not applicable)

## Visual Design Patterns

**Color Usage**:
- Chart colors: Predefined palette of 8 colors (blues, greens, yellows, reds, purples) (QueryChart.tsx:41-50)
- Primary bar/line: Dark blue (rgba(26, 54, 93, 0.8))
- Secondary bar/line: Accent blue (rgba(49, 130, 206, 0.8))
- Success: Green (rgba(56, 161, 105, 0.8))
- Warning: Yellow (rgba(214, 158, 46, 0.8))
- Error: Red (rgba(229, 62, 62, 0.8))
- Pie chart: Multi-color slices using full palette
- Borders: Slightly more opaque versions of fill colors (alpha: 1 vs 0.8)

**Typography**:
- Toggle button: 14px, medium weight
- Type selector buttons: 13-14px, regular or medium
- Chart labels (axes): 12px, regular
- Chart legend: 12px, regular
- Tooltip text: 12px, bold for value

**Spacing**:
- Toggle button margin: 12px top, 8px bottom
- Chart container padding: 16px all sides
- Type selector margin: 8px bottom
- Chart wrapper padding: 12px
- Button spacing: 4-8px between type selector buttons

**Visual Effects**:
- Borders: Light border around chart container
- Shadows: None or subtle shadow for elevation
- Animations: Chart.js default animations (bars grow, lines draw)
- Hover: Chart.js tooltips on data points
- Transitions: Smooth chart type transitions (fade/morph)

## Accessibility

**Keyboard Navigation**:
- **Tab**: Navigate to toggle button, then type selector buttons
- **Enter/Space**: Activate toggle or type selector button
- **Arrow Left/Right**: Navigate between type selector buttons

**Screen Reader Support**:
- Toggle button: "Show Chart" or "Hide Chart" announced
- Type selector: "Bar chart", "Line chart", "Pie chart" button labels
- Chart canvas: ARIA label describing chart type and data (e.g., "Bar chart showing sales by category")
- Chart data: Consider providing data table alternative (already visible above chart)

**Focus Management**:
- Focus visible on toggle button and type selector buttons
- Focus does not trap in chart container
- Focus order: toggle → bar → line → pie → next element

## Alternatives & Variations

**Similar UI Patterns**:
- **Always-visible chart**: Show chart by default without toggle (Pros: immediate visual; Cons: takes space for non-visual users)
- **Separate chart tab**: Put charts in separate tab/view (Pros: focused view; Cons: requires navigation)
- **Inline mini-chart**: Small sparkline-style chart inline with table row (Pros: compact; Cons: limited detail)
- **Full-screen chart modal**: Open chart in modal overlay (Pros: large view; Cons: loses context)

**When to Use**:
- Use toggleable chart when users may want table OR chart (not both simultaneously)
- Use always-visible when data is primarily consumed visually
- Use separate tab when charts are complex and need full attention
- Use auto-detection when data varies (sometimes chartable, sometimes not)

## Notes

- Chart component returns null (hidden) if data has no numeric columns or is otherwise not chartable
- analyzeData() looks for first string column as label and all numeric columns as datasets
- Pie charts only available when single numeric column (multi-series pie charts not supported)
- Color palette has 8 colors, repeats if more than 8 datasets (modulo logic: `i % CHART_COLORS.length`)
- Chart.js options set responsive: true and maintainAspectRatio: false for predictable sizing
- CSV download feature in QueryResultDisplay (ChatMessage.tsx:52-72) allows exporting raw data
- Chart canvas is a `<canvas>` element managed by Chart.js, not direct React rendering
- Toggle state (showChart) defaults to false, user must explicitly request chart
- Type selector state (chartType) defaults to 'bar' as most universally appropriate chart type
- Chart.js tooltips show on hover, displaying exact values for data points
- Legend position set to 'top' (QueryChart.tsx:138) to avoid overlapping with chart
